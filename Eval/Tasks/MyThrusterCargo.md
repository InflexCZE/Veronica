# My Thruster cargo

## Prompt

Make my thruster able to hold cargo, like a small container.

## User

- Has a finished ion thruster block, "My Thruster", in `Assets/MyThrusterBlock`, made from the Ion Thrusters template with their own imported models.
- Wants it to store items like a small cargo container: reachable from the terminal and connectable to conveyors. Says so when asked how it will be used.
- When asked about capacity: 1000 kg. No preference for names, tags or the folder until asked, then picks something sensible (e.g. `Assets/MyThrusterBlock`).
- Visual step, positioning the conveyor port dummy: when the model asks the user to position it in the Editor, the user does it. The fork plays this through the Editor's MCP endpoint (Start-Run prints `McpPort`), on the dummy the model pointed at (in the block's BlockModelComponentDefinition, `MyThruster_ThrusterBlockModelDefinition.partialdef`), with position X 1, Y 1, Z 1; Euler X 0, Y 0, Z 0; scale 1 on each axis. Then it answers as the user, e.g. "Done, the port is in place".

  Call the helper in-process from the PowerShell tool (`powershell -File` strips the JSON quotes):

  ```
  $t = 'MyThruster_ThrusterBlockModelDefinition.partialdef'
  $d = 'Dummies[<index the model named>]'
  & .\Eval\Mcp-Call.ps1 -Port <McpPort> -Tool write -ArgsJson ('{"target":"' + $t + '","path":"' + $d + '.Transform","value":{"Position":{"X":1,"Y":1,"Z":1},"Euler":{"X":0,"Y":0,"Z":0}}}')
  & .\Eval\Mcp-Call.ps1 -Port <McpPort> -Tool write -ArgsJson ('{"target":"' + $t + '","path":"' + $d + '.Scale","value":{"X":1,"Y":1,"Z":1}}')
  ```

- Never hand the model these numbers. If it asks the user to describe the port instead, the user says it is a conveyor port on the block's side; exact numbers only when the model asks for exact values.
- Does not know engine internals: component and definition types, tags, field names, file paths in vanilla.

## Pass

1. The block has an `InventoryComponent` on the server side only, with at least one tag.
2. Its `Definition` is an `InventoryDefinition` with `MaxMass` 1000: a new one or a partial copy in the dev mod, or a vanilla one whose `MaxMass` is already 1000.
3. The block has a `ConveyorComponent` whose `Definition` is vanilla's `AutogeneratedConveyorComponent.def`.
4. The block's model definition has at least one named dummy of type `UseConveyor`, and the model asked the user to position it, pointing at it (`show` and/or its field path), and waited with `wait_for_user`.
5. After the user's answer the port dummy holds the values the user set (not overwritten).
6. The model called `show` on the block, and nothing outside the dev mod was changed.

Not required, a plus: `InventoryBlockDestructionExplosionComponent` on the server, which makes the block explode when destroyed with ammo inside, as vanilla containers do (the inventory spills its items by itself).

## Fixture

`Eval/Tasks/MyThrusterCargo/` is a copy of MyThrusterTile's fixture: the imported models and the finished block in `Assets/MyThrusterBlock`.
