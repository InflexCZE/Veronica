---
name: block-inventory
description: Use when a block should store items, a new block or one that already exists.
---
Needs:
- the block: its prefab binding or any of its files
- capacity: the most mass it holds, in kg
- whether it connects to conveyors
- folder: a mod folder for new files, e.g. the block's own folder

Plan:
- Read the block's components: note which storage parts it already has and which are missing
- Get from the user what this needs: capacity, conveyors or not, and a folder when new files are made
- Set up the inventory: the InventoryComponent, and an InventoryDefinition with the user's capacity
- Set up the conveyor connection when the user wants it: the ConveyorComponent, and one port dummy per conveyor port; ask the user to move new ports into place in the Editor; read them back
- Show the block

Steps:
1. read(block) lists its components with sides, tags and definitions. A block made from a storage template already has an InventoryComponent and a ConveyorComponent; a block made for another function has neither. Every later step depends on what is there: fill what exists, add what is missing.
2. Ask the user for the capacity, whether it connects to conveyors, and a folder for new files, with wait_for_user. The template's and vanilla's capacities are not the user's.
3. Inventory:
   Missing: component_add(block, "InventoryComponent"). It goes to the server only, where items live.
   Its definition is an InventoryDefinition; MaxMass is the capacity in kg.
   - No definition yet: create_definition("InventoryDefinition", ...) in the folder, then write(block, "Components[InventoryComponent].Definition", <it>).
   - The block's own definition (in the mod): write(def, "MaxMass", <capacity>).
   - The user wants a vanilla container's capacity as it is: point the component at that container's InventoryDefinition. Never write to a vanilla file; for a changed value, create_partial a copy in the folder and write to the copy.
4. Conveyors:
   Missing: component_add(block, "ConveyorComponent", "AutogeneratedConveyorComponent"). That definition is shared by storage blocks: the conveyor network connects only at the block's port dummies.
   A port is a dummy in the block's BlockModelComponentDefinition whose Type is UseConveyor. read(def, "Dummies") first: keep the ports there.
   New port: element_add(def, "Dummies"), then write(def, "Dummies[i].Name", ..) and write(def, "Dummies[i].Type", "UseConveyor").
   Where a port sits is the user's call on their model: the model's geometry is not visible to you, so never compute positions. show(block), tell the user which dummy to move (its path, e.g. Dummies[1].Transform, and Dummies[1].Scale), that a port is a flat box facing out along its Z with equal X and Y scale, and that the Render View shows dummies under Preview Settings, Dummies; then wait_for_user. After the answer, read(def, "Dummies") and mark the item with the positions and scales read.

Show:
show(block). Ask the user to check the ports in the Render View.
