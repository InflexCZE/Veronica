---
name: block-inventory
description: Use when a block should store items, one create-block just made or one that already exists; it does not create the block.
---
Needs:
- the block: its prefab binding or any of its files
- capacity: the most mass it holds, in kg
- whether it connects to conveyors

Plan:
- Read the block's components: note which storage parts it already has and which are missing
- Get from the user what this needs: capacity, conveyors or not, and a folder when new files are made
- Set up the inventory: the InventoryComponent and its InventoryDefinition, with every value fitting what the user wants
- Set up the conveyor connection when the user wants it: the ConveyorComponent, and one port dummy per conveyor port, placed by copying or by the user; read them back
- Show the block

Steps:
1. read(block) lists its components: type, sides, tags, definition. A block made from a storage template already has an InventoryComponent and a ConveyorComponent; a block made for another function has neither.
2. Ask the user for the capacity, whether it connects to conveyors, and a folder for new files, with ask_user.
3. Inventory: a missing InventoryComponent: component_add(block, "InventoryComponent"). Its definition: the block's own when it has one; otherwise a vanilla storage block's InventoryDefinition as it is, or a create_partial copy of it when values differ. MaxMass is the capacity in kg.
4. Conveyors: missing, component_add(block, "ConveyorComponent", "AutogeneratedConveyorComponent"). That definition is shared by storage blocks: the conveyor network connects only at the block's port dummies.
   A port is a dummy whose Type is UseConveyor in the BlockModelComponentDefinition's Dummies: a flat box facing out along its Z, with equal X and Y scale. Keep the ports there; for each port more, element_add(def, "Dummies"), then write its Name and Type. Positions: for a model another block uses, copy the Transform and Scale of that block's ports; for a new model, the user places them: never compute positions. Then show(the block), ask the user to check or move them (name the paths, e.g. Dummies[1].Transform) with wait_for_user, read(def, "Dummies") again and mark the item with the positions and scales read back.

Show:
show(block). Ask the user to check the ports in the Render View.
