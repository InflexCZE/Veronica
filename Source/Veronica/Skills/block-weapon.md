---
name: block-weapon
description: Use when a block should fire projectiles like a gatling gun, optionally with an ammo of its own, one create-block just made or one that already exists; it does not create the block.
---
Needs:
- the block: its prefab binding or any of its files, made from the Gatling Cannon (Hit Scan) template
- the ammo: the vanilla gatling ammo, or a new ammo of its own with the user's changes (damage, range)
- conveyor ports: how many and on which faces; the user positions them in the Editor
- where it fires from: the barrel, positioned by the user in the Editor

Plan:
- Read the block and the vanilla gun's weapon definition
- Get from the user what this needs: the ammo and its changes, how many conveyor ports and where, whether it gets a muzzle flash, sound and aiming, and that they will place the dummies
- New ammo only: copy the ammo item, its AmmoDefinition and projectile, write the changes, map the item in the ammo configuration
- Add the weapon: its definition with the ammo, and the inventory it reloads from
- Connect it to the conveyors
- Add the barrel and port dummies; the user places them
- Show the block

Steps:
1. read(block) lists its components. The template brings no weapon, so the block cannot fire yet. read the vanilla gun's GatlingCannon200_ProjectileWeaponDefinition for the fields a weapon needs.
2. Ask the user, with ask_user, which ammo it fires and what changes, how many conveyor ports and on which faces, and whether it should have a muzzle flash, firing sound and aiming like the vanilla gun. Say they will place the barrel and the ports in the Editor.
3. New ammo, when asked:
   find_content("AmmoDefinitionsConfiguration") and read its AmmoTypes: it maps each ammo item to the AmmoDefinition a reload uses. Copy the vanilla item's AmmoDefinition and the projectile that AmmoDefinition names, not the ammo and projectile in the gun's own folder (only its state before the first reload).
   create_partial(<ammo item>, "copy", folder), create_partial(<AmmoDefinition>, "copy", folder), create_partial(<projectile>, "copy", folder).
   write(new AmmoDefinition, "ProjectileDefinition", <new projectile>). Write the user's changes on the new projectile from the values read there, e.g. each DamageTypeToDamage entry for damage.
   The mod's override of AmmoDefinitionsConfiguration: create_partial(config, "override", folder); when the mod already has one, the error names it: use that. element_add(override, "AmmoTypes", key=<new item>, value=<new AmmoDefinition>). Without the entry the game crashes when the gun reloads.
4. Weapon: create_partial(GatlingCannon200_ProjectileWeaponDefinition, "copy", folder). write(copy, "AmmoTypes[0]", <the ammo item>); keep BarrelDummyType.
   component_add(block, "ProjectileWeaponComponent", <the copy>). It adds the InventoryComponent the weapon reloads from; do not add a second one. Give that inventory a copy of the vanilla gun's InventoryDefinition: create_partial(<it>, "copy", folder), write it to the inventory component. Its WhitelistedItems admits only vanilla's ammo: element_add(copy, "WhitelistedItems", <the new ammo item>). The vanilla ammo stays admitted too: when the user wants only the new ammo, element_remove(copy, "WhitelistedItems[<vanilla ammo item>]"); otherwise tell the user both are accepted.
   component_add(block, "BlockPermissionsComponent").
5. Conveyors: component_add(block, "ConveyorComponent", "AutogeneratedConveyorComponent").
6. Dummies, on the block's BlockModelComponentDefinition: element_add(def, "Dummies") once for the barrel, once per port the user asked for, and once for the muzzle flash when the user wants it (it plays at a dummy of the type MuzzleFlash); the vanilla gun's other dummies (subparts, particles) belong to its own looks and are not added; write each one's Name and Type (the weapon's BarrelDummyType; UseConveyor for a port; MuzzleFlash for the flash). Shots leave at the barrel dummies. The vanilla gun's dummy positions fit its own model, not the user's: never copy or compute positions. show(the block), ask the user to place them (name the paths, e.g. Dummies[0].Transform) with wait_for_user, then read(def, "Dummies") again.
7. When the user wants them, muzzle flash, firing sound and aiming as the vanilla gun has them: component_add ProjectileWeaponEffectsComponent, ProjectileWeaponAudioComponent and ConvergeTargetingComponent, each with the vanilla gun's definition.

Show:
show(the block). Ask the user to check the barrel and ports in the Render View (Preview Settings, Dummies).
